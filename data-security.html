Security

數據安全聲明

最後更新：2026 年 7 月 12 日 · 版本 1.1

技術架構：Supabase + 靜態前端 傳輸：HTTPS / TLS 存取：Row Level Security（RLS）

重點摘要（30 秒讀完）

  • 所有表單與 API 通訊均經 HTTPS 加密；密碼以 bcrypt 雜湊存放，卍物所人員無法讀取您的明文密碼。
  • 資料庫啟用 RLS：您只能讀取自己的 profile 及與登入電郵相符的預訂；匿名訪客無法批量讀取他人資料。
  • 網站使用的 Supabase anon 金鑰僅具公開 API 權限，敏感操作受 RLS 及 Auth 保護。
  • 懷疑帳戶被盜或資料外洩？立即 security@wanwusuo.hk 通報，並更改密碼、登出所有裝置。

1. 安全承諾

卍物所採用業界常用的雲端安全實踐，而非自建未經審核的伺服器。我們的目標很具體：防止未授權讀取、防止篡改、在出問題時可追查並通知您。

我們不聲稱「絕對不可能被攻破」— 任何網站都不能這樣承諾。我們能做的是：限制攻擊面、加密傳輸與靜態資料、以資料庫規則約束誰能讀寫哪一行資料。

2. 系統架構（資料如何流動）

層級技術實際作用
前端 HTML / CSS / JavaScript（靜態託管） 展示頁面、收集表單、呼叫 Supabase API
API Supabase REST / Auth API 驗證身份、執行資料庫讀寫（受 RLS 約束）
認證 Supabase Auth Email 密碼、Google OAuth、Session 管理
資料庫 PostgreSQL（Supabase 託管） 儲存產品、預訂、投稿、用戶 profile
重點：卍物所沒有自架資料庫伺服器。個人資料主要存放於 Supabase 專案；前端程式碼不包含資料庫管理員密碼。

3. 傳輸安全

  • 瀏覽器 ↔ Supabase API：全程 HTTPS（TLS 1.2+），防止中途竊聽。
  • 密碼登入：密碼只在 TLS 通道內傳送一次至 Supabase Auth，隨即雜湊儲存，不會以明文寫入卍物所日誌。
  • Google 登入：OAuth 流程由 Google 與 Supabase 處理；卍物所網站不接觸您的 Google 密碼。
您可自查：瀏覽器網址列應顯示鎖頭圖示；若使用公共 Wi‑Fi，仍建議避免在不信任網路輸入密碼，可改用手機數據網絡。

4. 儲存、加密與備份

靜態加密
Supabase 對磁碟資料提供 encryption at rest（由平台管理金鑰）
備份
Supabase 定期自動備份；卍物所可於災難時依平台機制還原
密碼儲存
bcrypt 雜湊 — 即使資料庫外洩，攻擊者仍難以還原明文密碼
Session
JWT token 存於您的瀏覽器；登出即作廢當前 session

產品資料（名稱、價格、描述）為公開資訊，不含個人資料，可匿名讀取。

5. 身份驗證（實際機制）

方式技術細節我們能／不能看到什麼
Email + 密碼 Supabase Auth；最少 6 字元（平台預設） 能：電郵、profile 欄位
不能：明文密碼
Google OAuth OAuth 2.0；redirect 至 account.html 能：Google 授權的電郵、名稱、頭像 URL
不能：Google 密碼、Gmail 內容
重設密碼 Supabase 發送一次性連結至您的電郵 連結有效期限由 Supabase 控制；我們不會電話索取密碼
卍物所絕不會：透過 WhatsApp、Instagram 私訊或電話向您索取密碼。任何人這樣做，請視為詐騙並通報我們。

6. 資料庫存取規則（RLS 白話版）

PostgreSQL 的 Row Level Security 在資料庫層面強制「誰能讀哪一行」。以下為本網站已設定的主要規則：

資料表匿名訪客已登入用戶說明
wanwu_products 可讀（上架產品） 可讀 公開產品目錄
wanwu_market_reservations 可新增（提交預訂） 可新增；可讀電郵與自己帳戶相同的紀錄 無法瀏覽他人預訂
wanwu_art_submissions 可新增（投稿） 可新增 讀取僅限後台（第二階段或開自助查閱）
wanwu_profiles 不可讀寫 僅可讀寫自己的 profile 以 auth.uid() 比對

卍物所後台人員使用 Supabase Dashboard 或 service role 存取時，仍須登入受控帳戶，並遵循「必要知道」原則。

7. 前端 API 金鑰（anon key）代表什麼？

網站載入的 Supabase anon（公開）金鑰是設計上可暴露於前端的 — 它不等於資料庫管理員權限。真正保護資料的是：

  • RLS 政策（限制每一行誰能 SELECT / INSERT / UPDATE）
  • Auth JWT（登入後才附加用戶身份，解鎖「讀自己的資料」）
  • Supabase 專案層級的速率限制與監控
開發者說明：service_role 金鑰具完整權限，絕不嵌入網站前端。若您發現任何頁面洩露 service role key，請立即通報 security@wanwusuo.hk。

8. 員工與承辦商存取

  • 必要知道：只有處理預訂備貨、投稿審閱、帳戶支援的人員才會接觸個人資料。
  • Supabase：作為資料處理者，受其 DPA 及 SOC 2 等合規框架約束（詳見 supabase.com/security）。
  • 離職／終止合作：相關 Dashboard 帳戶存取於當日撤銷。
  • 裝置：後台存取應使用強密碼及雙重驗證（若平台支援）。

9. 離線與本機暫存風險

當 Supabase 暫時無法連線，app.js 可能將表單寫入您瀏覽器的 localStorage：

  • wanwu_reservations — 預訂表單備份
  • wanwu_submissions — 投稿表單備份

這些資料只存在您的裝置，不會自動上傳至他人。若您使用共用電腦：

  1. 提交成功後關閉分頁。
  2. 於瀏覽器設定清除「本網站資料」。
  3. 切勿在公共裝置勾選「記住密碼」。

10. 安全事件應變（若真的發生）

若我們發現或懷疑個人資料外洩、未授權存取或系統被入侵，將按以下步驟處理：

  1. 0–24 小時：遏制 — 停用受影響憑證、必要時暫停相關 API。
  2. 24–72 小時：調查 — 確認影響範圍（哪些表、哪些用戶、是否含密碼雜湊）。
  3. 72 小時內（視嚴重程度）：通知 — 以電郵告知受影響用戶可採取的行動（改密碼、留意釣魚等）。
  4. 後續：修補漏洞、更新 RLS 或流程、記錄事故報告以防再發。

若法律要求，我們亦會向香港相關機構通報。

11. 提交資料前 — 用戶自查清單

  • 確認網址為您信任的卍物所官方網域，而非仿冒釣魚站。
  • 密碼至少 8 字元，且不要與 Gmail、銀行等其他帳戶相同。
  • 預訂表單的電話是否正確 — 我們主要以此聯絡備貨。
  • 使用 Google 登入後，可於 Google 帳戶權限 檢視並撤銷卍物所存取。
  • 懷疑異常登入：立即於 我的帳戶 登出，並重設密碼。

12. 安全通報與查詢

發現漏洞、可疑連結或帳戶異常，請聯絡：

security@wanwusuo.hk

請在郵件中注明：發現時間、涉及頁面／功能、您的聯絡電郵（若需回覆）。我們會確認收到並於合理時間內跟進，不會因善意通報而追究通報者。
